# reproducible-research-pipeline

An AI coding skill for **reproducible, data-centric research and data pipelines**.
It is a skill for Claude Code and Codex, and also an `AGENTS.md` that Cursor,
Copilot, Gemini and other tools can read. It gives an AI coding agent one consistent
structure for turning raw data into trustworthy results:

> A stranger clones the repo, follows only the README, runs **one command**, and
> regenerates every dataset, table, figure and number in the report. The tests
> then tell them whether the data and the results can be trusted.

The conventions are distilled from UChicago FINM 32800 *Data Pipelines for
Quantitative Research* (see [Credits](#credits)). They cover:
- project layout
- configuration and secrets
- `pull_`/`load_` data modules
- a task DAG (`doit`)
- unit, data-validation and replication tests
- documented cleaning filters
- reports whose numbers are generated by code
- CI

The examples come from finance. The principles apply to any data-centric work.

## Who is this for

Anyone whose code turns **raw data into results** (a dataset, table, chart,
model or report): students, researchers, quants, data scientists and data
engineers. What matters is that the work is built around data, not how much
data there is. A 5 MB FRED pull benefits as much as a 400 GB TRACE panel.

| You are... | For example | What you get |
|---|---|---|
| Replicating a paper | Fama-French factors, a yield-curve model | Replication tests with pre-set tolerances, a one-command rebuild |
| Building a research dataset | Cleaned bond or options panel, CRSP-Compustat merge | Documented filters with row counts, data-validation tests |
| Doing factor or signal research | Return predictors, backtest inputs | Point-in-time discipline, testable analysis functions |
| Producing recurring reports | Monthly risk report, daily monitor, dashboard | Exhibits and numbers generated by code, validation before publishing, CI |
| Running data pipelines at work | Vendor ingestion, reconciliations | Idempotent tasks, data checks, orchestration patterns |
| Writing a thesis or course project | Final project, dissertation chapter | A repo a grader or referee can clone and rerun |
| Inheriting a messy repo | "Make this reproducible" | An audit script and a Definition of Done |

**Use it lightly, or not at all,** for library or algorithm development,
online services (low-latency trading, web apps), and throwaway exploration. A
few rules still help any Python project: keep config and secrets out of code,
pin dependencies, write tests, run CI.

**Adopt it in levels.** The skill tells the agent to pick the lowest level
that fits, so a quick script does not get a full project structure.

| Level | Situation | Adopt |
|---|---|---|
| 1 | A script you will rerun | Config + `.env`, pinned environment, README run commands |
| 2 | Shared or multi-step work | + task DAG, `pull_`/`load_` modules, unit tests, CI |
| 3 | Results others rely on | + data-validation and replication tests, filter waterfalls, generated report |
| 4 | Runs on a schedule | + orchestration, idempotency, drift checks, monitoring |

## Install

**Claude Code.** Clone into your skills folder. The repo root *is* the skill.
```bash
# all projects
git clone https://github.com/haocheng1130/reproducible-research-pipeline ~/.claude/skills/reproducible-research-pipeline
# or a single project
git clone https://github.com/haocheng1130/reproducible-research-pipeline <repo>/.claude/skills/reproducible-research-pipeline
```
Update later with `git pull` inside that folder. Claude loads the skill when a
task matches its description. You can also invoke it with
`/reproducible-research-pipeline`.

**Codex** (CLI, IDE extension and desktop app). Same skill format; clone into a
Codex skills folder. The repo root *is* the skill.
```bash
# all projects
git clone https://github.com/haocheng1130/reproducible-research-pipeline ~/.codex/skills/reproducible-research-pipeline
# or a single project
git clone https://github.com/haocheng1130/reproducible-research-pipeline <repo>/.agents/skills/reproducible-research-pipeline
```
Or ask Codex to install it with its built-in skill installer. Because the skill
sits at the repo root, the installer needs an explicit path and name:
```
Install the skill from GitHub repo haocheng1130/reproducible-research-pipeline
with --path . --name reproducible-research-pipeline
```
Restart Codex (or start a new session) afterwards. Codex loads the skill when a
task matches its description. Update later with `git pull` inside that folder
(the installer copies files without git, so reinstall to update).

**Other tools.** Copy `AGENTS.md` into your project:

| Tool | Where `AGENTS.md` goes |
|---|---|
| Codex without the skill, and other AGENTS.md readers | repo root, as `AGENTS.md` |
| Cursor | repo root, or `.cursor/rules/pipeline.mdc` with `alwaysApply: true` front matter |
| GitHub Copilot | `.github/copilot-instructions.md` |
| Gemini CLI | repo root, as `GEMINI.md` |
| Claude Code without the skill | repo root, plus a `CLAUDE.md` containing the line `@AGENTS.md` |
| Chat assistants | upload as project knowledge, or paste at the start of a chat |

Tool conventions change. If the file is not picked up, check the tool's docs
for its current instructions-file name.

## Use

Example requests once the skill or `AGENTS.md` is installed:
- "Scaffold a pipeline to replicate Fama-French (1993) from CRSP and Compustat."
- "Add a pull for the Fed's H.15 rates following the pull/load pattern."
- "Write data-validation tests for the cleaned TRACE panel."
- "Make this repo reproducible: audit it and fix what fails."

Audit any repository (Python 3.8+, no dependencies):
```bash
python ~/.claude/skills/reproducible-research-pipeline/scripts/audit_pipeline.py path/to/repo
```
It flags secrets in git history, hard-coded paths, unpinned dependencies,
`load_` functions that hit the network, pull tasks that `doit clean` would
delete, settings changes that will not trigger reruns, notebooks committed with
outputs, and more. The exit code is 1 if anything FAILs.

## Template project

[`templates/project/`](templates/project/) is a minimal complete pipeline
built on the Federal Reserve's public GSW yield curve. It shows every
convention working together:

```
pull (public CSV) → clean (filter chain + waterfall) → test (unit + data validation)
→ exhibits (LaTeX tables, figure, \newcommand stats) → jupytext notebook → LaTeX report → ChartBook site
```

Copy it, replace the yield-curve example with your own project, and keep the
structure. See its [README](templates/project/README.md) for setup. Re-pin
`requirements.txt` after your first install.

## Default stack (swappable)

conda + pip, PyDoit, python-decouple, pytest, jupytext, LaTeX, ChartBook,
GitHub Actions, Polars/Parquet for medium data, and Airflow for cross-project
orchestration. The skill keeps principles separate from tools. If a repository
already uses uv, pixi, Make, Quarto or Dagster, the agent follows the repo and
applies the principles.
